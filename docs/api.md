# Observation API

The direct Go endpoint uses `POST` and `GET` on `/api/v1/values`. Supply one
`X-API-Key` header for every request. There are no observation update or delete
operations. The [OpenAPI specification](openapi.md) is the machine-readable
contract; this page covers the common workflow.

## Send one observation

After `make dev`, create `value.json` in the repository root:

```json
{
  "id": "12345678-1234-4234-8234-123456789001",
  "sensor_id": "groundwater-01",
  "gateway_id": "demo",
  "sensor_type": "water-level",
  "timestamp": "2026-09-14T10:00:00Z",
  "value": 1.42,
  "unit": "m",
  "lon_lat": [16.3738, 48.2082],
  "location_id": 7,
  "metadata": {"packet_id": 42, "minimum": 1.39, "maximum": 1.47}
}
```

The example timestamp is historical; it will not trigger a live alert. For an
alert demonstration, use [development test data](test-data.md).

```sh
API_KEY="$(cat deploy/secrets/api_key)"
curl --fail-with-body --cacert deploy/certs/caddy-root.crt \
  -H "X-API-Key: $API_KEY" -H 'Content-Type: application/json' \
  --data-binary @value.json https://api.localhost/api/v1/values
```

The first accepted write returns `201` with `sequence` and `received_at` added by
the server. An identical retry returns `200` and the original identity. Reusing
the UUID with changed content returns `409`. Do not POST a GET response unchanged:
`sequence` and `received_at` are response-only fields.

The body may also be an array of 1–1000 observations. A batch commits in one
transaction or rolls back as a whole. A batch mixing new and identical replayed
records returns `201`.

## Read and page

```sh
curl --fail-with-body --cacert deploy/certs/caddy-root.crt \
  -H "X-API-Key: $API_KEY" \
  'https://api.localhost/api/v1/values?id=12345678-1234-4234-8234-123456789001'

curl --fail-with-body --cacert deploy/certs/caddy-root.crt \
  -H "X-API-Key: $API_KEY" \
  'https://api.localhost/api/v1/values?limit=100&after=0'
```

List reads return observations in commit-sequence order, including `[]` for an
empty result. `limit` defaults to 100 and accepts 1–1000. Follow the
`Link: <...>; rel="next"` header or pass `X-Next-Cursor` as the next `after`
value until there is no next-page header. This is a live traversal, not a snapshot.
Late event timestamps remain discoverable because ordering uses commit sequence.

## Validation and errors

`id` must be a lowercase UUID generated by the client. `timestamp` needs a
timezone and is normalized to UTC; precision beyond microseconds is rejected.
`value` must be finite, and `unit` is required. `lon_lat` is optional
`[longitude, latitude]` in WGS84 coordinates; `location_id` is an optional integer
from 0 to 9007199254740991. Either can be omitted or set to null. Optional
`metadata.minimum` and `metadata.maximum` must be supplied together and bound
`value`. See [locations](locations.md) and [measured ranges](measurement-ranges.md).

The API rejects unknown top-level fields, duplicate JSON keys, malformed types,
trailing documents, and excessive size/depth. Typical errors are `400` malformed
input, `401` authentication, `404` unknown ID, `409` conflicting ID, `413` large
body, `415` unsupported media type, `422` invalid observation, and `503` database
failure. Responses use `{"error":{"code":"...","message":"..."}}` without
database credentials or internal details.

The authenticated Node-RED demonstration route accepts the same observation
contract. Its status depends on the selected write backend; see
[write route semantics](architecture.md#write-route-semantics).
